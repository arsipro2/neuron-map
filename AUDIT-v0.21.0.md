# Проверка Neuron Map: 0.20.4 → 0.21.0

Проверены история проекта, frontend, store, физический движок/Worker, сохранение, импорт/экспорт, Rust/SQLite, конфигурация и сборка. Ниже — найденные и исправленные дефекты; это не обещание отсутствия любых возможных ошибок.

## Почему не открывались заметки

1. В `OptimizedGraphLayer` после `setSelected(id)` вызывался `setSelectedEdge(null)`. В исходном store второй вызов всегда устанавливал `selectedId: null`. Выбранный узел сразу терял выделение и редактор не получал заметку. Убрана лишняя команда; очистка связи теперь сохраняет выбор узла.
2. Область нажатия «+» имела постоянный радиус 32 пикселя, а расстояние до узла зависело от масштаба. На обычном/дальнем масштабе области перекрывались. Теперь визуальный «+» и его hit-test используют одну геометрию: смещение не меньше 44 пикселей, радиус нажатия 14 пикселей.
3. При повторной установке обработчиков очищался таймер hover, но его ref оставался непустым. Следующие движения могли перестать запускать наведение. Очистка теперь сбрасывает оба таймера.
4. Подписи загружали шрифт из внешнего CDN. При отказе загрузки React Suspense мог заблокировать сцену и обновления интерфейса. Noto Sans с латиницей/кириллицей включён локально, подписи изолированы отдельным Suspense. В тесте внешние запросы заблокированы, узлы и редактор продолжают работать. Редкие символы вне покрытия шрифта могут потребовать fallback-шрифта; это не должно блокировать сами узлы.
5. При клике на уже выбранный узел закрытая панель не открывалась: `selectedId` не менялся. Добавлен сигнал повторного выбора.

| После создания заметки прежний запрос фокусировки перекрывал последующие переходы из поиска | Выбирается более новый запрос фокусировки |

| Изменения во время записи могли отмечаться как Saved | Счётчик изменений сохраняет корректное состояние Dirty |

| Отсутствующие camera/preferences в snapshot оставляли более новые настройки | Отсутствие теперь восстанавливается как отсутствие |
| Desktop закрывался даже при ошибке финального сохранения | Закрытие отменяется, ошибка показывается пользователю |

| Web создавал пространство, но не сохранял его каталог; rename/import/delete были заглушками | Постоянный каталог, создание, переименование, переключение, импорт/экспорт и удаление |
| Footer всегда утверждал «Saved to SQLite», включая web и несохранённое состояние | Footer показывает реальное состояние сохранения |
| Read зависел от включения внутренних ссылок | Режим чтения доступен отдельно |
| Клавиатурная навигация мешала вводу, служебные сочетания могли включать действия | Проверки редактируемого поля/модификаторов, очистка удерживаемых клавиш |
| Старые неиспользуемые реализации содержали `connectNodes` без объявления и дублировали физику | Удалены неиспользуемые NoteNode3D, EdgeLine, контроллеры и старый solver в store |
| Ошибки типов cleanup и `postMessage` Worker ломали production build | Возвращаемые cleanup-функции имеют void; отдельные типы Worker |

| Поиск сериализовал тексты всех заметок при каждом изменении выделения | Вычисления поиска зависят от массива заметок |

## Реализация вложений

- Отдельные бинарные данные и лёгкие метаданные в заметках; содержимое файла не попадает в каждый React/render/snapshot-объект.
- Desktop: SQLite BLOB, транзакции записи графа, additive-миграция существующей схемы.
- Web: IndexedDB для файлов, localStorage для каталога/графа.
- Формат `.neuron` v2: встроенные base64-данные файлов. Импорт v1 остаётся совместимым.
- Проверки целостности: уникальные ID, ссылки только на существующие заметки, отсутствие дублированных связей, конечные координаты, наличие всех файлов, корректный base64 и совпадение размеров.
- Некорректный импорт отклоняется без создания частичного пространства. Неудачная SQLite-запись не заменяет прежние заметки.
- Файл до 20 MiB, суммарно до 64 MiB на пространство; `.neuron` до 100 MiB.
- Копирование нескольких файлов, drag-and-drop, скачивание/Save as, миниатюры распространённых растровых изображений и удаление привязки.

Предупреждение Vite о размере основного bundle остаётся: около 1.28 MB до gzip, включая 3D-библиотеки. Оно не мешает сборке. Ошибок TypeScript нет.

Историческое упоминание GPU picking не соответствует фактическому исходнику 0.20.4: там используется CPU raycast по InstancedMesh и screen-space fallback. В этой версии этот подход сохранён. Настоящий GPU picking следует рассматривать только после измерений на гораздо более крупных графах.

## Что улучшать дальше — в порядке пользы

1. **Undo/Redo и корзина заметок.** Вернуть удалённый узел со связями/вложениями, отменить раскладку и перенос. Это важнее новых эффектов.
2. **Экран резервных копий.** Показывать время, количество заметок и предварительный просмотр; восстанавливать выбранный snapshot одной командой. Backend уже умеет хранить и восстанавливать последние 20 снимков.
3. **Очистка файлов с учётом истории.** Удалять бинарные данные только если на них не ссылаются ни текущие заметки, ни сохранённые снимки. Сейчас они остаются до удаления пространства, поэтому длительная активная работа с вложениями может увеличивать размер базы.
4. **Удобное чтение.** Markdown, код с подсветкой, списки задач, таблицы; предпросмотр PDF и крупных изображений. Исходный текст должен сохраняться отдельно от рендера.
5. **Навигация по знаниям.** Теги, фильтры, «показать окружение выбранного узла», возврат к предыдущей заметке, поиск по именам вложений. Сохранить единую золотую палитру узлов.
6. **Дальнейшая оптимизация по измерениям.** Экран FPS/времени кадра/количества draw calls; кеш геометрии статичных связей и пространственный индекс для выбора. Возможность временно выключить частицы и подписи для очень больших карт. Не заменять рабочие взаимодействия непроверенным picking-механизмом.

Отдельные последующие инженерные задачи: разбиение большого OptimizedGraphLayer на взаимодействия/геометрию/подписи, очистка исторических CSS-переопределений и проверка на реальном WebKitGTK/Ubuntu. Это поможет избежать возвращения старых обработчиков при следующих изменениях.
