# Neuron Map 0.22.1

Локальная карта заметок: React / Three.js / Tauri / SQLite.
Версия 0.22.1 добавляет сценарии упаковки для Ubuntu, Windows и macOS, Docker-сборку Linux и ручной workflow GitHub Actions. Инструкция: **[BUILD-INSTALLERS.md](BUILD-INSTALLERS.md)**. Сохранены отмена действий, корзина, восстановление снимков, Markdown, предпросмотр файлов и новая навигация версии 0.22.0. Подробности прежних исправлений и проверки: [AUDIT-v0.22.0.md](AUDIT-v0.22.0.md).

## Установщик и запуск без localhost

Архив содержит исходники и готовый frontend; нативные установщики ещё нужно собрать. После установки программа запускается из меню системы: Node.js, Rust, Docker и localhost не нужны.

| Где выполняется команда | Команда после `npm ci` | Результат |
| --- | --- | --- |
| Ubuntu с зависимостями Tauri | `npm run build:linux` | DEB + AppImage |
| Windows с MSVC и Rust | `npm run build:windows` | EXE NSIS |
| Windows, установка без сети | `npm run build:windows:offline` | EXE со встроенным WebView2 |
| macOS с Xcode Tools и Rust | `npm run build:macos` | APP + DMG |
| macOS с двумя Rust targets | `npm run build:macos:universal` | Intel + Apple Silicon |

Docker и сборка всех платформ через GitHub Actions описаны в [инструкции](BUILD-INSTALLERS.md). Сборка требует интернета. Подписи издателя Windows и notarization macOS пока не подключены.

## Обновление и запуск из исходников

1. В прежней версии экспортируйте важные пространства в `.neuron` и закройте приложение.
2. Распакуйте новый архив в отдельную папку.
3. В этой папке выполните:

```bash
npm ci
npm run desktop
```

Эта команда запускает режим разработки с Vite на localhost. Для повседневного использования установите собранный DEB/EXE/DMG.

Нужны Node.js **22.13+** (рекомендуется 24 LTS), Rust stable и установленные зависимости Tauri для вашей ОС: https://v2.tauri.app/start/prerequisites/ . Если 0.21.0 уже запускалась, используйте то же системное окружение.

Идентификатор приложения `com.arsipro.neuronmap`, каталог данных и имя базы `neuron-map.sqlite3` сохранены. Миграция добавляет ревизию пространства и поля тегов/ссылок, не удаляя прежние заметки. **После обновления не открывайте эту базу старой версией приложения:** она не знает о корзине, ревизиях и новых полях. Новый `.neuron` имеет версию формата 3; импорт старых форматов 1 и 2 поддерживается.

Архив содержит исходники и готовый frontend в `dist`. Нативный установщик нужно собрать на целевой машине:

```bash
npm run build           # проверка версий, TypeScript, frontend
npm run dev:web         # браузерная версия
npm run preview         # готовый frontend
npm run desktop:build   # установщик для текущей ОС
```

Файлы PDF.js для автономного просмотра подготавливаются автоматически перед запуском и сборкой. Первый `npm ci` требует сети; приложение не обращается к CDN за шрифтами или PDF-ресурсами.

## Что появилось

- **Undo / Redo** в верхней панели. Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y вне текстовых полей. В поле ввода работает обычная отмена редактора. История хранит до 50 состояний текущего сеанса, включая перемещения и раскладку; переключение пространства очищает её.
- **Корзина** в меню пространства → **Recovery & backups**. Заметка удаляется вместе со связями, но сохраняет содержимое и файлы. Возвращать связанные заметки можно в любом порядке. Корзина сохраняется после перезапуска.
- **Snapshots**: до 20 снимков с датой, количеством заметок, файлов и первыми заголовками. Перед восстановлением создаётся страховочный снимок текущих, в том числе ещё не сохранённых правок. Восстановление заменяет граф и камеру выбранным состоянием.
- **Save backup copy…**: отдельный `.neuron` со всеми текущими заметками, корзиной и вложениями. Эта команда не требует успешного предварительного сохранения в базу. Копию можно перенести на другой диск. Создавайте её вручную; автоматическая отправка в облако не настроена.
- **Markdown Read**: заголовки, списки, задачи, таблицы, цитаты и подсветка кода. HTML не исполняется; внешние изображения не загружаются автоматически.
- **Preview** для локальных изображений и PDF, кнопки страниц PDF. Защищённые паролем и неподдерживаемые PDF можно сохранить и открыть во внешнем просмотрщике.
- **Теги**, поиск по `#тегу`, названиям вложений, заголовку и тексту. Несколько слов сужают результаты; например `#research данные`.
- **Insert note link** с фильтром заголовков; `[[Заголовок]]` и `[[Заголовок|подпись]]`. После связывания ссылка сохраняет адресата при переименовании. Одинаковые заголовки нужно разрешать через выбор заметки. Удалённый адресат помечается отсутствующим и не заменяется другой заметкой с тем же названием.
- **Mentioned in** показывает обратные ссылки, стрелки вверху возвращают к ранее открытым заметкам. Для переходов включите **Internal note navigation** в Settings.
- **Show neighbors** временно оставляет выбранную заметку и её непосредственных соседей. **Show all** возвращает всю карту.
- **Reduced motion** останавливает частицы связей. При обычной анимации неподвижная геометрия связей используется повторно.

## Узлы и вложения

Клик по узлу открывает заметку; повторный клик возвращает закрытый Editor. Движение больше 6 пикселей начинает перетаскивание. «+» создаёт связанную заметку или соединяет с существующей. Escape, потеря фокуса, удаление исходного узла и отпускание за пределами сцены отменяют незавершённый жест.

**+ Attach files** и перетаскивание в блок вложений принимают любые типы файлов. Во время копирования видны номер и имя файла. Нажатие на имя сохраняет копию через системный диалог в desktop или скачивание в web. Файлы хранятся внутри приложения, исходный путь не требуется. Привязку можно удалить и вернуть через Undo.

Лимиты: **20 MiB на файл**, **64 MiB вложений на пространство вместе с корзиной**, `.neuron` до **100 MiB**. Поддерживаются до 20 000 заметок и 100 000 связей вместе с корзиной; координаты ограничены диапазоном ±100 000. Это защитные пределы формата, а не обещание одинакового FPS на любой карте.

**Recovery & backups → Files & copies → Check unused files** проверяет лишние бинарные данные. Desktop удаляет их только после подтверждения, сохраняя всё, на что ссылаются текущие заметки, корзина, undo/redo или удерживаемые снимки. Браузер показывает кандидатов, но не удаляет их: другой открытый таб может иметь несохранённые ссылки. Освобождённые страницы SQLite повторно используются базой; размер файла на диске не обязан сразу уменьшиться.

## Сохранение

- Автосохранение — через **5 минут после первого изменения**. Дальнейшие правки не отодвигают срок.
- **Save / Ctrl+S** сохраняет сразу и создаёт снимок. Переключение пространства и штатное закрытие desktop ожидают окончания записи.
- При ошибке записи выполняются до трёх повторов через 2, 5 и 15 секунд. Сообщение остаётся видимым. Доступны **Retry**, **Save backup copy…**, **Reload saved**. Последняя команда отбрасывает локальные правки после подтверждения.
- Ревизия защищает от записи устаревшего состояния. Конфликт не повторяется автоматически. Desktop также регистрирует единственный экземпляр приложения.
- Браузер хранит граф в localStorage, файлы и снимки в IndexedDB. Это отдельные данные от desktop. Очистка данных сайта удаляет браузерную копию.
- **Export…** сначала сохраняет обычным способом, затем экспортирует. **Save backup copy…** берёт данные из памяти и подходит для аварийного сохранения. **Import…** создаёт новое пространство.

## Проверки

```bash
npm run check:versions
npm run test:unit
npm run test:storage
npx playwright install chromium
npm run test:e2e -- --grep "trash and attached" --timeout=30000 --workers=1
npm run test:production
```

Playwright настроен на один worker и 30 секунд на тест; запускайте отдельные сценарии или небольшие группы через `--grep`. В ограниченных окружениях можно явно указать существующий Chromium через `PLAYWRIGHT_EXECUTABLE_PATH`; менять настройки проекта не нужно.

`test:storage` компилирует настоящий SQLite-модуль отдельно от GTK/WebKit. Итог: 10 тестов логики, 15 SQLite и 14 браузерных сценариев прошли; npm audit — 0 известных уязвимостей. Подробные результаты и ограничения нативной проверки указаны в отчёте.

## Следующие шаги

1. Проверить новый desktop на вашей Ubuntu: запуск, системные диалоги, повторный запуск второго экземпляра и сохранение при закрытии.
2. Собрать установщики по `BUILD-INSTALLERS.md`, проверить на трёх ОС и проверить обновление с копией настоящей базы.
3. Измерить время кадра и выбор узлов на реальных больших картах; по результатам решать, нужен ли пространственный индекс или GPU picking.
4. Затем добавить полнотекстовый поиск по PDF/документам и удобное редактирование Markdown. Синхронизация и автоматические внешние резервные копии требуют отдельного выбора места хранения.
