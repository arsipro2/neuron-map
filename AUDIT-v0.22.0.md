# Neuron Map 0.22.0 — реализация и повторная проверка

## Результат

Реализованы семь исправлений из повторного анализа, история действий, корзина, экран восстановления, независимые резервные копии, Markdown, локальный просмотр изображений/PDF и навигация по заметкам. Сохранены крупные кремово-золотые узлы и прежний порядок автосохранения.

## Исправленные дефекты

| Дефект | Исправление и проверка |
|---|---|
| Удаление исходного узла во время перетаскивания «+» оставляло незавершённый жест и блокировало дальнейшие клики | Подписка отменяет жест при удалении/замене графа; завершение использует `finally`; отсутствующий источник не создаёт заметку. Браузерный регрессионный тест проверяет следующий клик и Undo. |
| После ошибки сохранения не было повторной попытки; обычный Export зависел от успешной записи | До трёх повторов с актуальными правками, устойчивое сообщение, кнопка Retry. Отдельный экспорт копии из памяти проверен при искусственном QuotaExceededError. |
| Устаревшее окно могло полностью перезаписать более свежий граф | SQLite-транзакция сравнивает ожидаемую ревизию; конфликт не записывается. Добавлен single-instance plugin. Для web используются Web Locks и ревизии. Проверены независимые устаревшие состояния SQLite и два браузерных таба. |
| После сбоя Worker новый Worker не получал исходный граф | Каждый новый Worker сначала получает `init`; при сбое во время перетаскивания доступно прямое обновление позиции. Регрессионный тест проверяет порядок `init → dragStart`. |
| Конечная координата могла переполниться при переводе в Float32 | Единые пределы координат, числа заметок/связей; некорректные физические сообщения отбрасываются. Проверены чрезмерные координаты и Infinity в сообщении Worker. |
| Предварительный снимок мог вытеснить выбранный старейший снимок перед восстановлением | Выбранное состояние читается до добавления страховочного снимка. В SQLite операция атомарна; текущие несохранённые правки передаются в транзакцию. Проверено восстановление старейшего из 20 и последующее возвращение страховочной копии. |
| Web и Rust по-разному принимали имена файлов и base64 | Согласованы проверки путей, метаданных и канонических завершающих битов base64. Общие JSON-фикстуры используются обоими наборами тестов. |

## Новые возможности

- До 50 состояний Undo/Redo в сеансе; сохранение позиций до переноса/автораскладки.
- Постоянная корзина с заметками, связями и файлами. Восстановление связанных узлов в любом порядке.
- Экран последних 20 снимков: время, счётчики и первые заголовки. Отдельные `.neuron`-копии из текущей памяти; native Save As или браузерное скачивание.
- Очистка неиспользуемых SQLite BLOB учитывает текущую запись, корзину, снимки и ссылки из Undo/Redo. В web доступна только оценка, поскольку несохранённые данные другого таба неизвестны.
- Markdown/GFM и подсветка кода, сохранение исходного текста, отключённый HTML и автоматическая загрузка внешних изображений.
- Просмотр распространённых растровых форматов и PDF; страничная навигация, ограничение размера canvas, освобождение объектов/рендеров при закрытии. PDF.js подключён через совместимую legacy-сборку; шрифты, CMaps и WASM лежат локально.
- Теги, поиск по файлам и `#тегам`, обратные ссылки, история переходов, фильтр соседей и выбор адресата wiki-ссылки.
- Wiki-ссылка хранит стабильное соответствие заголовка идентификатору. Переименование не ломает переход, а удалённый адресат не заменяется одноимённой заметкой.
- Индикация имени и номера копируемого файла. Защита клавиатурных действий при открытых диалогах.

Во время проверок исправлены ошибки новых функций: одинаковые React-ключи полей тегов и вложений; PDF API, требующий более нового JS-движка; повторная оптимизация Vite при первом открытии PDF; разрешение локальных blob-модулей шрифтового Worker в CSP. Повторные целевые проверки прошли.

## Зависимости и предупреждения

| Компонент | Версия / результат |
|---|---|
| Tauri API / CLI / Rust | 2.12.1; автоматическая проверка согласованности |
| Vite | 7.3.6 |
| Playwright | 1.63.0 |
| PDF.js | 6.4.299, legacy browser build |
| npm audit | 0 известных уязвимостей, включая dev-зависимости |
| install-scripts | В package.json перечислены разрешённые версии esbuild 0.25.12 и 0.28.2; глобальное разрешение всех install scripts не используется |
| Vite chunk warning | Устранено разбиением основного JS: приложение ~98 kB, отдельные части Three.js/React Three; Markdown/PDF загружаются по требованию |

Текущий PDF worker — отдельный файл примерно 1.32 MB. Общий размер 3D-библиотек не исчез: разделение помогает загрузке и кешированию, а не доказывает рост FPS.

CSP ограничивает внешние ресурсы и запрещает object/frame. `blob:` и `unsafe-eval` оставлены для используемого движка шрифтовых Worker; это совместимая политика, не максимально строгая. Работоспособность готового frontend с этой политикой проверена отдельно.

Предупреждения `NO_COLOR/FORCE_COLOR` и `Unknown env config http-proxy` в среде проверки происходят из её переменных окружения; конфигурация проекта их не добавляет.

| Граф 1200 узлов / 1799 связей | Выбор, чтение, отмена жеста; внешние запросы отсутствуют |
| Экспорт/импорт произвольных бинарных и пустых файлов | Побайтовое совпадение |
| Вложения в корзине после перезапуска | Восстановлены вместе с байтами |
| Геометрия статичных связей | Повторно используется между кадрами частиц; отдельный браузерный тест |

Итого **39 тестов прошли**. У Playwright один worker, timeout **30 секунд на тест**; внешние запуски также ограничивались 60–90 секундами. Исправленные тесты перезапускались точечно.

Обычный Chromium был заблокирован ограничением IPC среды, а запрос расширенных прав отклонён её политикой. Все успешные браузерные проверки проведены доступным Chromium Headless Shell 133 в исходных ограничениях, через Playwright 1.63.0. Загрузка нового Chromium 153 вернула повреждённый архив. Это не проверка текущего WebKitGTK или всех браузеров.

Полный `cargo check` нативной оболочки остановился в системных зависимостях `glib-sys/gobject-sys`: нет `pkg-config` и GTK/WebKit SDK. Установка системных пакетов недоступна в этой среде. SQLite-модуль скомпилирован отдельно. Нативное окно, single-instance на реальном DBus, системные диалоги и готовый `.deb`/AppImage здесь **не проверены**.

## Следующие действия

1. Экспортировать важные пространства из прежней версии, закрыть её и запустить новую по README.
2. На вашей Ubuntu проверить второй запуск, сохранение при закрытии, Save As, восстановление и импорт копии настоящего пространства; затем собрать установщик.
3. Измерить графику на ваших данных и GPU. Пространственный индекс выбора и GPU picking пока не добавлены: они требуют отдельного измерения узких мест.
4. Следующие продуктовые улучшения: полнотекстовый поиск внутри вложений, удобный Markdown-редактор, автоматические копии на выбранный внешний носитель. Синхронизация между устройствами остаётся отдельной задачей.

История действий хранится в памяти сеанса; постоянное восстановление обеспечивают корзина и снимки. Встроенные снимки находятся в той же базе и не защищают от потери диска — для этого нужна отдельная копия. Старую версию после миграции следует держать закрытой, чтобы она не записывала незнакомые ей поля.
